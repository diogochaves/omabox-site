Install

Three minutes, then ask your agent.

omabox installs from its git repository, into your home. On Arch it asks for sudo only to install packages it needs that you don't have yet; on other distributions it prints the line that installs them and stops.

git clone https://github.com/diogochaves/omabox && cd omabox && ./install.sh

Or ask your agent: "Install omabox. The guide is at omabox.app/install.md." It stops for you where sudo or a choice of yours comes up.

Where it runs

Linux with Hyprland 0.56 or later and its Lua config (0.56.2 and 0.57.1 are tested), and a GPU: AMD and Intel iGPUs and NVIDIA RTX cards are tested.

Omarchy 4.5

Boxes are Omarchy's own desktop: its config, its shell, your theme. Omarchy 4.0 still works, deprecated: omabox drops it in its first release after 2026-12-04. omarchy update brings 4.5.

Arch, Fedora 45, Debian sid, openSUSE Tumbleweed

Boxes are plain Hyprland, with your shell as their bar if you want one. Each is tested in a VM of its own, install.sh through to real boxes; plain Arch runs the whole test suite. Fedora's Hyprland comes from a COPR; on Debian sid, Hyprland 0.57.0 drops every GPU app in a box (fixed in 0.57.1: omabox doctor warns).

Also

  • Rust: omabox is one binary, built by ./install.sh. With no cargo, it installs Arch's rust, or names your distribution's; the first build fetches its crates.
  • nftables (nft), only if you set protected ports
  • For agents to reach for it on their own, one the skill is installed for: Claude Code, Codex, OpenCode, pi or Hermes

aquamarine, and NVIDIA

install.sh builds a private copy of aquamarine (Hyprland's backend library) inside the clone; your system's isn't touched. Headless boxes on NVIDIA need its fix until a system aquamarine has PR #415 (0.16.0 does), and it carries omabox's own fixes for boxes you drive (a held key, your pointer across a box's monitor windows), which no system copy has.

With several GPUs, omabox config gpu picks the one headless boxes render on, and omabox gpu release takes down the boxes on one before you hand it to a VM.

Install and check

Install

$ git clone https://github.com/diogochaves/omabox && cd omabox
$ ./install.sh           # packages, omabox, links; asks about the bar widget and the guard
$ ./install.sh --check   # then starts a box, screenshots it, takes it down

install.sh checks your distribution's packages under their own names. On Arch (with or without Omarchy) it installs what is missing, with sudo. On Debian, Fedora and openSUSE it prints the command that does (sudo apt install …, sudo dnf install …, sudo zypper install …) and stops: run it, then ./install.sh again. Then it builds omabox and aquamarine and runs omabox setup.

What setup does

  • Links ~/.local/bin/omabox
  • Puts the agent skill wherever Omarchy puts its own skills (~/.agents, ~/.claude, ~/.codex, ~/.pi/agent, ~/.hermes)
  • On Omarchy, links the bar widget and asks whether to put it in your bar
  • Asks whether to turn on the agent guard

Later, by hand: omarchy plugin enable chaves.omabox, omabox guard on.

A box that won't start: omabox doctor

It checks what a box needs (Hyprland and its config, bubblewrap, pasta, user namespaces, the render nodes, the programs a box runs) and, for each one that fails, prints the line that installs it for your distribution. It changes nothing. --smoke also starts a box, takes a shot and takes it down; --json for a script.

$ omabox doctor
ok    hyprland       Hyprland 0.57.2 (Lua config)
ok    bwrap          bubblewrap 0.13.1
ok    userns         unprivileged user namespaces: unshare and bwrap make them
ok    tun            /dev/net/tun, a connected box's network
...
$ omabox doctor --smoke

From 0.x to 1.x.

Take your boxes down, then git pull && ./install.sh in one go, and restart agents running in ai-jail. The 1.0 changelog lists each form that changed.

Step by step
  1. Take your boxes down first.
    $ omabox down --all
  2. Pull and build in one go. Until install.sh has run, omabox is missing, new agent sessions start without the guard, and agents in ai-jail don't start.
    $ git pull && ./install.sh
  3. Restart agents running in ai-jail. A jail started before the upgrade keeps its old relay.
  4. Scripts on an old form are told what to write. A form 0.9 warned about is refused, with a line naming what to write instead.
  5. Nothing to move. Every path in your home stays where it was: the omabox link, ai-jail's maps, the broker's unit, the guard's hook.

Update and remove

Update

$ git pull && ./install.sh

Run it after a Hyprland upgrade too. omabox --version says which aquamarine boxes use. After an upgrade the bar runs the old widget until the shell restarts; its panel says so. Boxes already up keep the Hyprland config they started with: omabox reload gives one the new one. What changed in each release is in the changelog.

Remove

$ omabox down --all                         # every box
$ omabox setup --remove                     # guard and broker off, widget off, links gone
$ rm -rf ~/.config/omabox ~/.cache/omabox   # settings, and box HOMEs a crash left behind
$ rm -rf ~/.local/share/omabox              # saves, if you made any

Run setup --remove before you delete the clone: once omabox is gone there is no guard off left to run. Then delete the clone. The packages install.sh added stay; it printed them as missing: if there were any. The README has the details.

What a box can't do

Worth knowing before you hand it a task.

  • A plain box has no bar unless you give it a shell: no launcher, tray host or notification server, so an app that waits for a tray or notifies finds nobody there.
  • No system bus. Apps that need system services (disks, NetworkManager, bluetooth, power) open with errors or not at all: a box has none, by design.
  • No real hardware. A box's monitors are virtual (as many as you like), so real ones (their modes, HDR and VRR, a real hotplug), real input devices and suspend never run in it, and its lock screen takes no real password. With --audio it gets a speaker nobody hears, never your sound card. For the installer, system services or a reboot, a VM is the tool.
  • No wgpu apps on NVIDIA. Apps drawn with wgpu (eframe's default renderer, iced, Bevy) don't start in a box on NVIDIA: give them a GL renderer, or a box on an AMD or Intel GPU. Develop has the details.
  • Not a security boundary. A box shares your kernel, your GPU and, by default, your network. For a fence around the agent, use ai-jail with it. What a box does keep out, and the test for each rule: Safety.
  • Of the agents the skill is installed for, Claude Code and OpenCode were checked end to end; Codex, pi and Hermes find the skill.

Something didn't work on your machine? Run omabox doctor and tell us what happened. Another GPU, another distro or a config nothing like ours is the test we don't have.

Questions people ask first

Do I type omabox commands myself?

You can, but you'll rarely need to. Ask your agent: "start a box with the app running so I can try it" gets you a window you drive, and the agent keeps changing the app in it while you test.

Do I need Omarchy?

No. On Omarchy 4.5 a box is Omarchy's desktop; on Arch without Omarchy, Fedora 45, Debian sid and openSUSE Tumbleweed it is a plain Hyprland, with your shell as its bar if you want one. Any distro needs Hyprland 0.56 or later with its Lua config. Where it runs →

Does it work with my shell?

Yes, one at a time: DMS, Noctalia, Caelestia, Waybar or a Quickshell config, as a plain box's bar (up --desktop plain --shell CMD) or with your whole desktop copied into a box (up --desktop desk). Desktops →

Is omabox part of Omarchy?

No. omabox is an independent community project and is not made or endorsed by the Omarchy project. Report problems on omabox's GitHub, not to Omarchy.

Will an update break my scripts?

Exit codes and --json fields keep their meaning within 1.x, and only grow. 1.0 itself removed the forms 0.9 warned about, each refused with a line naming what to write. The contract →

Why Rust?

One binary, built by ./install.sh. It leaves nothing half-done when you stop it, enters a box without nsenter, and keeps a box's commands off your terminal. The commands are the same.

Can two agents test at the same time?

Yes. Each Claude Code or Codex session gets its own box, named after its repo or worktree and its session. Subagents take a box each, with omabox brief.

Is it a sandbox?

No, it is not a security boundary. It keeps apps off your desktop and never gets your secrets, input devices or seat, but it shares your kernel, GPU and, unless you pass --net isolated, your network. For a fence around the agent, use ai-jail; for hostile code, a VM. Safety →

Which GPUs does it work on?

AMD, Intel and NVIDIA. On NVIDIA, headless boxes need a fix to aquamarine that install.sh builds for you; Where it runs has the details.

Does peeking slow the agent down?

No. Peek only copies frames out of the box.
