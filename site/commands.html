What your scripts can rely on.

      
omabox is mostly used by agents, which read its warnings; a script or CI reads exit codes and
        --json. From 1.0, within 1.x:

      

        
KeptOr only added to

          
Exit codes, and every --json field: its name, type and meaning. New fields may come, so read the ones you need by name.

          

            
0done, or the condition held

            
1it ran and failed, or the answer is no

            
2called wrongly

            
124not in time

            
125run: omabox's own failure, never the command's

          

        
WarnedChanged only after a warning

          
Commands, options, config keys and OMABOX_* variables. The old form works for one more minor release,
            with omabox: deprecated: on stderr naming the new one. OMABOX_STRICT=1 refuses it at once, for CI.

          
$ OMABOX_STRICT=1 omabox check run -- ./scenario.sh

        
CarriedSaves and baselines

          
A save made by a 1.x starts with any later 1.x. A check baseline approved by a 1.x compares with any later 1.x, or is refused (“approve again”), never compared wrongly.

Message wording, help text, defaults, and what Hyprland and other programs report through omabox.
