1.0.0 · a contract your scripts can keep · changelog →

Everything from 0.6 to 1.0 that you would notice, in one tab.

  • A contract your scripts can keep

    Within 1.x, exit codes and --json fields stay as they are or only grow. A command or option that has to change warns for one release first; OMABOX_STRICT=1 makes that warning an error, for CI.

    The contract →

  • One binary, in Rust

    Stopped mid-step, omabox undoes that step: an interrupted up takes its box down, a stopped recording keeps its video. Entering a box is its own now, not nsenter's: run -- true in about 24 ms.

  • Ports no box reaches

    Your database stays out of every box, on loopback or any of your host's addresses.

    $ omabox config protect-ports 5432,8080
    Ports →

  • The app answers in text

    tree, check, record and audio, from 0.6 to 0.9: an agent asks the app, compares it with a baseline, films it and hears it.

    On /develop →

0.9.0 · 2026-10-20 · the last release before 1.0 · changelog →

  • A brief for a subagent

    About 15 lines a lead agent pastes into a subagent's prompt in place of the whole skill.

    $ omabox brief -b app-menu

  • Help that fits

    omabox help CMD is the command's lines and options; --long has the prose.

  • Exit codes that mean one thing

    Called wrong is exit 2, with the nearest option or command named, in every command.

    $ omabox help exit-codes

  • Holds in a video

    record hold pauses a take on the video's own clock; record --for films something that moves by itself.

0.8.0 · 2026-10-20 · visual checks · changelog →

  • Visual checks

    check compares an app's or a plugin's look with a baseline, in a box where only what is tested moves.

    $ omabox check run -- ./visual.sh

  • Your own Quickshell

    Run the box's shell on a Quickshell build of yours.

    $ omabox up --quickshell ~/src/quickshell/build

  • Your fonts, in every box

    Read-only, so an app draws in a box the way it draws for you.

  • Says what's in the way

    click --window says when a toast or another layer covers the point it aims at.

0.7.0 · 2026-10-16 · held keys, your binds · changelog →

  • Hold a key across commands

    Hold Shift, click three things, let go.

    $ omabox keys down:shift

  • Your binds, in the box

    A box loads your Hyprland bindings and input settings.

  • A journal in every box, CPU per thread

    Logs of what ran, and where the time went.

  • A crash says it crashed

    With the signal, so an agent doesn't wait on a window that will never come.

0.6.0 · 2026-10-14 · the app as text · changelog →

  • A window as text

    An app's controls as compact text, for a fraction of a shot's tokens.

    $ omabox tree --find 'dark mode'

  • Videos with sound and marks

    up --audio, record mark, and every monitor in one video.

  • Your whole shell in a box

    Every plugin and your shell.json, without touching your bar.

    $ omabox up --desk-shell

  • Boxes nobody will take down

    ls names them; down --orphans clears them.

0.5.0 · 2026-10-09 · several monitors in one box · changelog →

  • Several monitors in one box

    As many as a test needs, any size, scale and place, a bar on each. Add and unplug them while the box runs.

    $ omabox up --monitor 1080x1920 --monitor 2560x1440,scale=1.6,below
    Every desk you don't have →

  • A monitor that drops off and comes back

    output drop --cycles does what a monitor waking up does, again and again, until your shell crashes. gdb gives the backtrace.

  • Your theme, live

    --theme-dir puts the theme you are editing in the box, every save with it; --theme starts a box on the theme you name.

  • Only what changed

    shot --changed sends only what an action changed: a menu opening is about 65 image tokens instead of 1.5k. shot --burst catches a transition in frames.

0.4.3 · 2026-10-01 · plugin and app work · changelog →

  • It says why a plugin isn't in the bar

    up --plugin and restart-shell print why the shell didn't load it: a manifest it refuses, a QML error.

  • The box says what it tested

    ls --json records the Omarchy version, the theme and each plugin's commit, so a screenshot in a pull request says exactly what it shows.

  • Steps written for your desktop, done in a box

    The agent skill maps "link the plugin", "edit shell.json" and the rest to the box, where they can't change your bar.

0.4.2 · 2026-10-01 · an Omarchy checkout in a box · changelog →

  • Your Omarchy checkout, not installed

    up --omarchy DIR runs a box on that tree's config, shell and scripts, as omarchy dev link would, without touching your system.

    $ omabox up dev --omarchy ~/src/omarchy

  • Omarchy's own binds work in a box

    The browser bind opens the browser in the box, and Omarchy's shell restart restarts the box's shell.

  • The bar widget, offered at setup

    omabox setup asks to put it in your bar, and the widget says when it is older than the omabox installed.

0.4.0 · 2026-10-01 · set up in one command · changelog →

  • One command to set up, one to undo

    omabox setup links omabox, the agent skill and the bar widget and offers the guard; setup --remove undoes all of it.

    Install →

  • Your system's aquamarine

    Boxes run on the aquamarine you have, and use the private build only for what needs its fix.

0.3.0 · 2026-09-30 · agents see inside a box · changelog →

  • Inside the box's Hyprland

    omabox lua evaluates Lua in it, log reads its logs, events stamps what it reports: an agent checks without a screenshot.

    $ omabox lua 'hl.get_active_window()'

  • Sign in once, every box starts signed in

    omabox save keeps a box's HOME, keyring included; boxes started --from it open already set up.

  • Agents inside ai-jail drive boxes of their own

    omabox broker on, with no change to ai-jail: the jail's boxes get only what the jail has. omabox itself is not a security boundary.

    ai-jail with omabox →

  • Your Hyprland build in a box

    up --hyprland PATH runs a build of yours instead of the installed one, beside a stock box to compare.

0.2.0 · 2026-09-29 · windows, waits and a box per agent · changelog →

  • Windows as targets

    omabox windows lists where each window is and what covers it; shot, click and keys take --window.

  • Wait for the screen, not a timer

    omabox wait returns when the screen holds still, a window opens or a command succeeds: no more sleep.

  • A box per agent session

    Two agents in one repo get a box each, named after the session, and each goes down when its agent exits.

  • A network of its own

    Every box gets its own network: it reaches the internet and your servers, and you reach its. Much of this release is Tyler South's (@btsouth).

0.1.0 · 2026-09-25 · the first release · changelog →

  • Boxes

    omabox up: a whole Omarchy desktop, invisible, for an agent to launch, click, type and screenshot in.

  • Tests that touch the desktop

    omabox run -- ctest runs them against a box's own tray, notifications and keyring.

  • Peek, or drive it yourself

    omabox peek watches a box; up --interactive makes one a window you drive.

  • The skill, the guard and the bar widget

    Agents reach for a box on their own, the opt-in guard catches a window they forget to box, and the widget lists every box in your bar.
