1.6.0 · 2026-11-26 · a desk in one command · changelog →

  • A known desk in one command

    A JSON file lists the windows: the command, the workspace, floating, sized or pinned. scene opens each and returns when every one is where it was asked; applied again, it opens nothing twice. For testing an overview, a workspace list or a window switcher.

    $ omabox up --scene desk.json

  • How the screen ran

    frames times the compositor's frames over a stretch or around an action: the median, the worst cases and how many came late. A number to choose an animation by, on each GPU.

    $ omabox frames -- keys super+Tab

  • A recording that counts its frames

    record --frames-log says which captured frame each frame of the video holds, and which it repeated or skipped. A lag read from a video is then a count, not an estimate.

    $ omabox record --fps 60 --frames-log pan.tsv -- keys super+Tab

  • One layer of several

    A frame drawn as one layer per screen edge shares a namespace. --layer NAME:top, :bottom, :left or :right picks one, so a script needs no address that changes at every restart.

    $ omabox tree --layer myframe:top --find Wi-Fi

1.5.0 · 2026-11-20 · looks in one call · changelog →

  • Look in one call

    An app, a shell plugin, a theme or a web page: a shot, what it shows as text and the problems it logged, exit 1 when there are some. In your box when it's up, a throwaway one when not.

    $ omabox look app -- ./build/app
    On /develop →

  • Theme checks

    What a person would notice: text too faint to read, a colour no fallback resolves, a wallpaper too small or too bright for the theme's mode. No stock theme trips them.

    $ omabox look theme ~/code/my-theme

  • A bar's text, without a shot

    tree --layer lists the text the shell draws, so a widget is read and clicked by what it says, not by OCR.

    $ omabox tree --layer omarchy-bar --find cups

  • What it wrote, and who did what

    snapshot and diff list what a program left in the box HOME; log commands says which agent ran what against a box. The skill's core is 3.6 KB, short enough for small local models.

    $ omabox diff before
    On /develop →

1.4.0 · 2026-11-07 · your own desktop in a box · changelog →

  • Your own desktop in a box

    Your Hyprland config, your shell (DMS, Noctalia, Caelestia, Waybar or a Quickshell config) and your look, on a copy of your files, held awake between an agent's steps. Secrets stay out, and up says what it left out.

    $ omabox up --desktop desk
    Your own desk →

  • A window's state, set

    window --fullscreen and --maximize set it instead of toggling it, so an agent that doesn't know the state can't flip it the wrong way.

    $ omabox window --window myapp --fullscreen

  • The real LAN, when you name it

    --net host shares your host's network, for tools that scan devices on it. Never the default, refused inside ai-jail, and not for code you don't trust: omabox is not a security boundary.

1.3.0 · 2026-11-07 · any Hyprland · changelog →

  • Plain boxes, beyond Omarchy

    Hyprland with a small config of omabox's, on Arch without Omarchy, Fedora, Debian and openSUSE; install.sh and doctor know each one's packages.

    $ omabox up --desktop plain
    Plain Hyprland →

  • Your shell as a plain box's bar

    --shell runs DMS, a Quickshell config or any shell you name, waits until it draws and says when it crashes.

    $ omabox up --desktop plain --shell 'dms run'

  • Another Hyprland, whole

    --hyprland DIR takes a package, a prefix or a build folder, its libraries and hyprctl with it: Hyprland 0.57 in a box on a desktop that has 0.56.

    On /develop →

  • Notifications as text, real drag-and-drop

    log notifications and wait notification say what an app notified; drag does real drag-and-drop in GTK, Chromium and Qt apps.

    $ omabox wait notification 'Saved'

1.1.0 · 2026-10-31 · new ways to drive and check a box · changelog →

  • Wait on the app's own words

    wait tree returns when the accessibility tree holds a text, a toast that lasts a second included; --expect tree stops a chain of steps when one's effect isn't the one wanted.

    $ omabox wait tree 'Saved' --window myapp

  • Jobs, without pgrep

    jobs, stop, wait job and wait log: a run -d program listed, stopped and waited for by its pid, never by a name your desktop shares.

    $ omabox jobs

  • Click what it says

    click --find clicks what the tree names; find and click --image find a picture where there is no tree.

    $ omabox click --window myapp --find Save

  • Can this machine run boxes?

    omabox doctor checks what a box needs and prints the line that installs what's missing, changing nothing.

    $ omabox doctor
    Install →

1.0.0 · 2026-10-27 · a contract your scripts can keep · changelog →

Everything from 0.6 to 1.0 that you would notice, in one tab.

  • A contract your scripts can keep

    Within 1.x, exit codes and --json fields stay as they are or only grow. A command or option that has to change warns for one release first; OMABOX_STRICT=1 makes that warning an error, for CI.

    The contract →

  • One binary, in Rust

    Stopped mid-step, omabox undoes that step: an interrupted up takes its box down, a stopped recording keeps its video. Entering a box is its own now, not nsenter's: run -- true in about 3 ms.

  • Ports no box reaches

    Your database stays out of every box, on loopback or any of your host's addresses.

    $ omabox config protect-ports 5432,8080
    Ports →

  • The app answers in text

    tree, check, record and audio, from 0.6 to 0.9: an agent asks the app, compares it with a baseline, films it and hears it.

    On /develop →

0.9.0 · 2026-10-20 · the last release before 1.0 · changelog →

  • A brief for a subagent

    About 15 lines a lead agent pastes into a subagent's prompt in place of the whole skill.

    $ omabox brief -b app-menu

  • Help that fits

    omabox help CMD is the command's lines and options; --long has the prose.

  • Exit codes that mean one thing

    Called wrong is exit 2, with the nearest option or command named, in every command.

    $ omabox help exit-codes

  • Holds in a video

    record hold pauses a take on the video's own clock; record --for films something that moves by itself.

0.5.0 · 2026-10-09 · several monitors in one box · changelog →

  • Several monitors in one box

    As many as a test needs, any size, scale and place, a bar on each. Add and unplug them while the box runs.

    $ omabox up --monitor 1080x1920 --monitor 2560x1440,scale=1.6,below
    Every desk you don't have →

  • A monitor that drops off and comes back

    output drop --cycles does what a monitor waking up does, again and again, until your shell crashes. gdb gives the backtrace.

  • Your theme, live

    --theme-dir puts the theme you are editing in the box, every save with it; --theme starts a box on the theme you name.

  • Only what changed

    shot --changed sends only what an action changed: a menu opening is about 65 image tokens instead of 1.5k. shot --burst catches a transition in frames.

0.3.0 · 2026-09-30 · agents see inside a box · changelog →

  • Inside the box's Hyprland

    omabox lua evaluates Lua in it, log reads its logs, events stamps what it reports: an agent checks without a screenshot.

    $ omabox lua 'hl.get_active_window()'

  • Sign in once, every box starts signed in

    omabox save keeps a box's HOME, keyring included; boxes started --from it open already set up.

  • Agents inside ai-jail drive boxes of their own

    omabox broker on, with no change to ai-jail: the jail's boxes get only what the jail has. omabox itself is not a security boundary.

    ai-jail with omabox →

  • Your Hyprland build in a box

    up --hyprland PATH runs a build of yours instead of the installed one, beside a stock box to compare.

0.2.0 · 2026-09-29 · windows, waits and a box per agent · changelog →

  • Windows as targets

    omabox windows lists where each window is and what covers it; shot, click and keys take --window.

  • Wait for the screen, not a timer

    omabox wait returns when the screen holds still, a window opens or a command succeeds: no more sleep.

  • A box per agent session

    Two agents in one repo get a box each, named after the session, and each goes down when its agent exits.

  • A network of its own

    Every box gets its own network: it reaches the internet and your servers, and you reach its. Much of this release is Tyler South's (@btsouth).
