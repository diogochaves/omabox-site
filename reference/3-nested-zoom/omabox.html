This is what a box is: a whole Omarchy desktop on a private screen and a private session bus. Here is how an agent uses one, from start to finish.

01 · the problem

Your agent needs to see the app

Agents build GUI apps, bar plugins and themes, and check their work by running it. On your desktop that means windows tiling into your workspace, focus jumping while you type, notifications piling up.

~/code/app — nvim
chromium · agent
Build finished · app
focus stolen
02 · up

It starts a box instead

Omarchy's own Hyprland config, bar, menu, tray and notifications, with your theme and bar layout. It starts in 3–4 s, uses about 500 MB and draws nothing on your screen.

$ omabox up
omabox: box 'app-5cc72cdc' up (1920x1080@60)
$ omabox run -d -- ./build/src/myapp
03 · drive

It drives the box the way you would

Real key events reach Hyprland's binds. It clicks in a window's own coordinates, captures covered windows, and waits for the screen to settle instead of sleeping.

$ omabox keys super+space
$ omabox wait still           new
$ omabox click --window foot 120 40  new
$ omabox shot --window foot   new
04 · watch

You watch, or take over

Peek at any box in a live, view-only window that never takes your focus, or open one as a window and drive it yourself.

$ omabox peek -b app-5cc72cdc
omabox: peek at box 'app-5cc72cdc' on workspace 9
05 · down

It cleans up after itself

omabox down ends everything in the box and deletes its home. A forgotten box goes down by itself after 30 minutes idle. There is nothing to put back.

$ omabox down
omabox: box 'app-5cc72cdc' down
and yes

A box can run inside a box

That is how this page is built, and how omabox's own demo was recorded: a box played the desktop, and every omabox up in it started a box inside that box.

Agents use it on their own.

Install once. From then on your agents reach for a box whenever a task touches the desktop, without you asking and without changing your projects.

A skill your agents already load

install.sh puts the omabox skill wherever Omarchy puts its own. Agents load it when a task involves a GUI app, a screenshot, a shell plugin or tests that touch the desktop.

Claude CodeCodexOpenCodepiHermes

A box for every session

Each Claude Code or Codex session gets its own box, named after the repo and the session, like app-5cc72cdc. Two agents in one repo never share one or take each other's down. A session's box goes down after 30 minutes idle.

Your projects stay as they are

When a project's instructions say "run the app" or "screenshot with grim", the agent does exactly that, in a box.

The guard, for when advice isn't enough opt-in

A skill is advice. With omabox guard on, your agents' shells get a display that doesn't exist, so a stray window fails with an error the skill explains and the work moves into a box. When you ask for your real desktop ("switch my theme"), the agent runs that one command with omabox host -- CMD, on the record. It stops accidents; it isn't a fence.

Look inside, or take the wheel.

Boxes are invisible until you want to see one. Then you can watch without disturbing the agent, or drive the box yourself.

Peek

omabox peek opens a live, view-only window of a box on workspace 9 without taking your focus. It only copies frames out, so the agent never notices. Its clicks show up as marks.

Interactive

omabox up --interactive makes a box a real window you drive with your own keyboard and mouse. SUPER+ALT+ESC sends SUPER keys to the box. Closing the window ends it.

The bar widget

The omabox mark in your Omarchy bar lists every box, with peek, screenshot and down for each, and a button for a new interactive box. Try the copy next to this: click a box, or focus the panel and use its keys.

box tests-94b2f15c · depth 4

For the work that has to touch a desktop.

Test suites that talk to the tray and the keyring, shell plugins you edit and reload, apps that must not reach your real services.

Tests that need a session

With no box up, run starts a throwaway one, mounts your repo as an overlay that is thrown away, runs the tests and tears it down. Tray and notification tests register with the box's bar, not yours.

$ omabox run -- ctest --test-dir build

Omarchy shell plugins

Mount a plugin read-only into a box's bar, edit it, reload the shell, look. --stock-bar shows it the way most people's bars will.

$ omabox up --plugin ~/code/myplugin
$ omabox restart-shell

Away from your real services

An isolated box has only a loopback and the host ports you list, so an app can't reach your real local servers by mistake.

$ omabox up --net isolated --allow 8081

Any screen, and what it costs

Any size and refresh rate, changed live, and the GPU time of one box's processes without your desktop's added in.

$ omabox up --size 3440x1440@144
$ omabox gpu 10

What a box can touch

What goes in, what never does, and what stays off until you ask.

12345fence-2d6a0b91--net isolated22:20

box fence-2d6a0b91 · depth 5

Your desktop stays yours.

A box gets a fake home seeded with your theme, and never your secrets, your input devices or your real seat.

In the box

  • The repo you started it from, read-only, at the same path
  • Your theme, bar layout and terminal settings
  • mise's toolchains, so node, python and uv work as on the host
  • Its own screen, session bus and throwaway keyring

Never in the box

  • Your HOME, ~/.ssh, keyrings, API keys and tokens
  • Your input devices, display card and seat
  • The system bus and your real runtime dir
  • Your own ~/.config/hypr

Off until you ask

  • Network isolation: --net isolated
  • A systemd user manager: --systemd
  • X11 apps: --xwayland
  • Your real desktop, one command at a time: omabox host

A box keeps an app off your desktop and out of your config. It is not a security boundary: it shares your kernel and GPU, and by default your network. For code you don't trust, use --net isolated at least, or a VM.

box install-c07e5a19 · depth 7 · the bottom

Three minutes, then your agents take it from there.

What you need

  • Omarchy 4 on Arch, with Hyprland 0.56+
  • A GPU render node. Tested on AMD and Intel iGPUs and an NVIDIA RTX 4070 SUPER.
  • A patched aquamarine until a release ships PR #415. install.sh builds it privately; your system's copy isn't touched.

Install

$ git clone https://github.com/diogochaves/omabox && cd omabox
$ ./install.sh           # asks before turning the guard on
$ ./install.sh --check   # starts a box, screenshots it, takes it down
$ omarchy plugin enable chaves.omabox   # the bar widget

Update with git pull && ./install.sh. To remove it, see the README.

Questions people ask first

Does it work without Omarchy?

No. A box runs your host's own Omarchy: its Hyprland config, its shell and your theme. That is what makes it faithful, and why it needs Omarchy 4 and Hyprland 0.56 or later.

Is it a sandbox?

No. It keeps an app off your desktop and out of your config, and never gets your secrets, input devices or seat. It shares your kernel, GPU and, unless you pass --net isolated, your network. For code you don't trust, use a VM.

Which agents does it work with?

The skill is installed for Claude Code, Codex, OpenCode, pi and Hermes. Any other agent can use the CLI, and omabox guard exec -- AGENT starts it under the guard with a box of its own.

Does it work on NVIDIA?

Yes. It was tested on an RTX 4070 SUPER with driver 615.71.09. With several GPUs, point a box at one with OMABOX_RENDER_NODE.

Does peeking slow the agent down?

No. Peek only copies frames out of the box.
